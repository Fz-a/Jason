# 终端内容源文件

**你要改的就是这个目录里的 `.md`。** 改完跑一条命令，终端就更新了。

```bash
npm run content:check      # 只校验，有错会告诉你是哪个文件第几行
npm run content:build      # 编译成终端读取的数据
```

---

## 四个分区

```
en/                          英文（站点只有这一种语言）
  content.md    引导之旅的六章
  recap.md      走完之后的速览页 + 左侧导航标题
  ui.md         界面文案：按钮、输入框、命令手册、带变量的回复
  theater.md    装饰：开机动画、neofetch、提交历史、ASCII 画廊
```

**`content.md` 一章一个问题**，章节编号就是左侧导航的序号：

| 章节 | 回答 |
|------|------|
| 01 | 我是谁 |
| 02 | 我解决什么问题 |
| 03 | 哪些项目证明了这一点 |
| 04 | 我的技术纵深在哪里 |
| 05 | 为什么下一步是低空经济 |
| 06 | 找我 |
| 07（在 `recap.md`） | 一屏回顾 |

改的频率大概是：`content.md` 每周，`ui.md` 偶尔，`theater.md` 几乎不动。

## 小节：一章可以说好几段

**每个 `field` 块开启一个小节**，渲染顺序是
`header` → `body` → 内容块 → `footer`。

所以一章可以「说一段 → 给证据 → 再说更深的一段」重复任意多次：

````
```field
header = 我的技术闭环
footer = 我最擅长的不是某一个工具，而是跨层理解一个智能设备为什么能运行。
```

```numbered
1. Hardware | 原理图、PCB、MCU ...
2. Embedded | C/C++、STM32 / ESP32 ...
```

```field ← 这就开启了第二小节
header = 我看一个系统的方式
body = 输入是什么？位置和状态是否可信？
footer = 这也是我走向智能无人系统的原因。
```
````

**想加一个新的论点，就多写一个 `field` 块。** 不需要碰任何 `.tsx`。

## 一个例子

假设你想把第 3 章的项目清单加一项：

1. 打开 `en/content.md`
2. 找到 `## 03 · 哪些项目证明了这一点` 那段，在 `items` 块里加一行：

   ````
   ```items
   农机北斗 RTK | 参与高精度定位终端与现场应用
   新型号遥控器 | 给客户做的下一代，带屏幕 ← 新增这行
   ```
   ````

3. `npm run content:check && npm run content:build`
4. 刷新页面

**只有这一种改法。** 不要动 `app/components/terminal/` 里的任何文件——
那些是编译产物，改了会被下次编译覆盖。
